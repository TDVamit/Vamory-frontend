Frontend Guide: Accessing Public Folders & Files (Query Param Approach)
1. How to Make a Folder Public
Use the endpoint:
POST /api/v1/folders/{folder_id}/make-public
This will recursively assign the same public_token to the folder, all subfolders, and all files.
2. Accessing Folders and Files
A. Get Public Folder Info
Endpoint:
GET /api/v1/public/folders?token={public_token}&folder_id={folder_id}
public_token: The token returned from the make-public endpoint.
folder_id: The MongoDB ID of the folder you want to access (root or subfolder).
Example:
GET http://localhost:8000/api/v1/public/folders?token=4ba58c6c-8c17-43c0-a275-461a2b1fe6bf&folder_id=60f7c2b8e1b1c8a1b8e1b1c8
Success Response:
{
  "_id": "60f7c2b8e1b1c8a1b8e1b1c8",
  "name": "Shared Root",
  "is_public": true,
  "public_token": "4ba58c6c-8c17-43c0-a275-461a2b1fe6bf",
  // ...other fields...
}
Failure Response:
{ "detail": "Public folder not found or not public" }
B. Get Files in a Public Folder
Endpoint:
GET /api/v1/public/files?token={public_token}&folder_id={folder_id}
Returns all files in the specified folder.
Example:
GET http://localhost:8000/api/v1/public/files?token=4ba58c6c-8c17-43c0-a275-461a2b1fe6bf&folder_id=60f7c2b8e1b1c8a1b8e1b1c8
Success Response:
{
  "data": [
    {
      "_id": "fileid1",
      "filename": "photo.jpg",
      "file_type": "IMAGE",
      "s3_url": "https://s3.amazonaws.com/...",
      // ...other file fields...
    }
  ],
  "meta": {
    "total": 1,
    "page": 1,
    "per_page": 20
  }
}
Failure Response:
{ "detail": "Public folder not found or not public" }
C. Get a Specific File by ID
Endpoint:
GET /api/v1/public/files/file?token={public_token}&file_id={file_id}
Returns the file if it’s in a public folder tree with the given token.
Example:
GET http://localhost:8000/api/v1/public/files/file?token=4ba58c6c-8c17-43c0-a275-461a2b1fe6bf&file_id=abc123
Success Response:
{
  "_id": "abc123",
  "filename": "photo.jpg",
  "file_type": "IMAGE",
  "s3_url": "https://s3.amazonaws.com/...",
  // ...other file fields...
}
Failure Responses:
File not found
  { "detail": "File not found" }
  Not in public folder or token invalid:
  { "detail": "File is not in a public folder or token invalid" }
  3. How to Use These APIs in the Frontend
A. Initial Load (Root)
When a user opens a public link, extract the public_token and the root folder_id.
Fetch the root folder info and files:
/api/v1/public/folders?token={public_token}&folder_id={root_folder_id}
/api/v1/public/files?token={public_token}&folder_id={root_folder_id}
B. Navigating Subfolders
As the user clicks into subfolders, use the subfolder’s _id as folder_id in the same endpoints.
Always use the same public_token.
C. File Previews/Downloads
Use the file’s s3_url (from the API response) for preview or download.
Thumbnails (if available) are in thumbnail_s3_url.
D. Error Handling
If you get a 404 or error message, show a “Not found or not shared” message.
If the token is invalid or revoked, show an “Invalid or expired link” message.
E. Security
No authentication is required for these endpoints.
Only folders and files under the public tree are accessible.
